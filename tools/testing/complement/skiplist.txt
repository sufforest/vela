# Complement test skip list.
#
# Tests listed here are excluded from Complement runs via `go test -skip`.
# Each line is a regex anchored against the Go test name. Empty lines
# and `#` comments are ignored.
#
# Add a test here ONLY when:
# 1. It's known to fail because of a feature gap or open bug, AND
# 2. It's slow enough to consume meaningful wall time (>10s typical),
#    so skipping reclaims iteration speed.
#
# Each entry should be paired with a one-line note about why. When the
# underlying gap is closed, remove the line and re-run the suite.
#
# Re-evaluate the list on every Complement upgrade — the upstream test
# names occasionally rename.

# v10/v12 incompatibility: test asserts the room creator appears in
# m.room.power_levels.users with PL > users_default. v12 (MSC4289)
# REQUIRES creators to be absent from users — implicit power 100 via
# the create event's sender + additional_creators field. Vela is
# v12-only by design, so this test is structurally inapplicable.
^TestPowerLevels$

# --- v10/v12 spec-mandated rejections (NOT bugs) ---
# spec: rooms/v12.md auth-rule 10.4:
#   "If the `users` property in `content` contains the `sender` of
#    the `m.room.create` event or any of the `additional_creators`
#    array (if present) ... reject."
# These tests put the room creator in `m.room.power_levels.users`
# to grant them PL 100. v12 servers MUST reject the PUT — we do,
# with 400 M_BAD_JSON, which leaves the test's downstream steps
# unreachable. Not a bug; vela is v12-only by design.
^TestDemotingUsersViaUsersDefault$
^TestRoomMembers/Parallel/Test_that_we_can_be_reinvited_to_a_room_we_created$
^TestRoomDeleteAlias/Parallel/Users_with_sufficient_power-level_can_delete_other's_aliases$
^TestRoomDeleteAlias/Parallel/Regular_users_can_add_and_delete_aliases_when_m.room.aliases_is_restricted$
